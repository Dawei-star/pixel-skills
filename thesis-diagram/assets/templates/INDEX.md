# 结构模板

`scripts/layout.py` 的输入样板。改内容不改结构——版式、层距、分支偏移、汇合点、消息行高都由脚本管。

| 文件 | 版式 | 演示的东西 |
|---|---|---|
| `flowchart-gb1526.json` | `linear` + `"style": "gb1526"` | **国标流程图**：跑道形起止、直角矩形、两个菱形判定、一次中线汇合 |
| `activity-linear.json` | `linear`（不写 style） | **UML 活动图**：实心圆起、带环圆止、圆角动作框、两个判定、一条回溯线 |
| `usecase-three-column.json` | `usecase` | 参与者 + 4 主用例列 + 4 被包含用例列、include 关系 |
| `sequence.json` | `sequence` | 6 参与者、10 条消息、自调用、调用/返回两种线型 |

前两份是同一个 `linear` 版式的两套符号，只差一个 `"style"` 字段——**先问用户要哪套，再挑对应的那份改**（见 SKILL.md「流程类图：先问，再画」），别拿 UML 样板改出个国标图。

```bash
python scripts/layout.py assets/templates/activity-linear.json -o 图4-2.svg
python scripts/check_diagram.py 图4-2.svg
```

## 这是样板，不是范式

三份文件里的业务词（农情数据、识别结果复核、巡田照片）是拿来让结构看得懂的，**必须整份换成你的题目内容**，包括节点数和层级——14 个图元、4+4 个用例、6 个参与者都只是演示规模，不是建议规模，更不是配额。

脚本对这些文件零引用（`grep templates scripts/*.py` 无结果），删了整个目录 `layout.py` 照跑。它唯一的作用是省掉"对着空白想结构"那一步。

## 加节点的实测行为

1. **主链插一节**：`nodes` 加一条、把 `edges` 里原来那根拆成两根。坐标不用管。
2. **分支加长**：同一条分支上的节点写**同一个** `col`（-1 或 1），脚本按 rank 自动往下排。
3. **左右分支不等长**：能排，汇合线会自动一长一短（长的那侧从更上层直落下来）。读得懂，但评审看着不对称——尽量把两条分支配平到相同节点数。
4. **时序图加参与者**：往 `participants` 里加一项，宽度自动涨 118px。6 个参与者已经到 700px，A4 正文栏约 600px，再多就得缩图或拆图。
5. **时序图加消息**：插进 `messages` 任意位置即可，行高固定 38px，上下自动重排。返回消息写 `"kind": "return"`（线型只认这个字段，箭头方向由 `from`/`to` 决定）。

四路分支排不下（只有 `-1 / 0 / 1` 三列），会报同层同列冲突。真需要四路，说明这张图该拆成两张，或者该换 PlantUML。

**时序图不支持 UML 组合片段**（`alt` / `opt` / `loop` / `par` 那个带标签的方框）。论文里确实常用，但那需要嵌套矩形加分区，是另一套排版逻辑，目前得回 PlantUML。
