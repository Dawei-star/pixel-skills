# 论文图表

## 三条硬规则

1. **一套语法贯穿全篇**。流程类图只能走 GB 1526（跑道形终止符 + 直角矩形处理）或 UML 活动图（实心圆起、带环圆止），二者不可混用。评审未必因"没按国标"扣分，但一定会因前后不一致质疑。
2. **图元超过 7 个就不许手写坐标**。8 个以上还靠肉眼算 x/y，几乎必然出现连线穿框、层距忽宽忽窄、分支左右不对称——而且图渲染出来之前你自己看不出来。交给 `scripts/layout.py`（只写结构）或 PlantUML（只写语法）。
3. **校验不通过不算画完**。`check_diagram.py` 退出码不为 0 就继续改，最多 3 轮；3 轮仍不过说明规模或通道选错了，降规模重来，别在错的路线上磨。

手写坐标只留给"单个符号"和"极简示意"（≤7 个图元，一屏能看全）。这是唯一能靠眼睛保证正确的规模。

## 生成通道选路

| 图种 / 场景 | 通道 | 坐标由谁定 |
|---|---|---|
| 流程图、活动图、状态图、时序图 | PlantUML | 引擎 |
| 流程 / 活动图 · 要贴合 `assets` 的版式 | `scripts/layout.py`（`linear`） | 脚本 |
| 用例图 · 标准版 | PlantUML | 引擎 |
| 用例图 · 主用例一列 + 被包含用例右移一层 | `scripts/layout.py`（`usecase`） | 脚本 |
| E-R 图 | PlantUML `entity`（IE 鸦脚） | 引擎 |
| 单个符号 / 极简示意（≤7 图元） | 手写 SVG | 你，且只有这时可以 |

PlantUML 出图发虚或错位时，先调 `skinparam`（`monochrome true`、`shadowing false`、`linetype ortho`），不要急着换工具。

## 结构交给脚本，坐标不要自己算

`scripts/layout.py` 吃一份结构 JSON，吐出画好的 SVG。它负责分层、分支左右、汇合、回溯绕行、viewBox——这些全是"看一眼好、看二十眼看不过来"的活。

```bash
python scripts/layout.py 流程.json -o 图4-2.svg
python scripts/preview.py 图4-2.svg -o 图4-2.png    # 自查用，别交付
```

```json
{
  "layout": "linear",
  "nodes": [
    {"id": "s", "text": "开始", "shape": "start"},
    {"id": "a", "text": "采集数据", "shape": "process"},
    {"id": "d", "text": "完整？", "shape": "decision"},
    {"id": "x", "text": "标记异常", "shape": "process", "col": 1},
    {"id": "b", "text": "特征提取", "shape": "process"},
    {"id": "e", "text": "结束", "shape": "end"}
  ],
  "edges": [
    ["s", "a"], ["a", "d"],
    {"from": "d", "to": "b", "label": "是"},
    {"from": "d", "to": "x", "label": "否"},
    ["x", "b"], ["b", "e"]
  ]
}
```

要点：`shape` 取 `start` / `end` / `process` / `terminator` / `decision` / `io`；判定节点的分支目标写 `col: -1`（左）或 `1`（右），只写一个时另一个自动落到中线；两条都不写照出边顺序摊成左右；多层汇合到中线会自动画汇合点和单根主干；同层同列两个节点直接报错，不会画出一张"看起来排好了"的重叠图。

用例图同理：`"layout": "usecase"`，节点 `col: 0` 是主用例列、`1` 是被包含列，`actors` 列参与者，边的 `kind` 取 `assoc` / `include` / `extend`，连线和边界矩形全自动。尺寸、字号、线宽与 `assets/examples` 里的样板一致。

**起步别从空白写，改 `assets/templates/` 里的样板**：`activity-linear.json`（14 图元、两处分支汇合、一条回溯线）和 `usecase-three-column.json`。加节点只是加两行 JSON。

**脚本报错就改 JSON，不要回头去手改 SVG**——手改一次，后面所有重排都作废。

### 它能画什么、不能画什么

`layout.py` 不是通用图描述语言，是**两种论文版式的生成器**。它的价值恰恰在于不通用：层级、分支左右、间距由 JSON 显式指定，所以出来的图横平竖直、样式一致，模型也没有机会把坐标算歪。换成真正的通用布局引擎（DOT、自动排布），排得下任何图，但排不出这套模板的样子。

| 版式 | 覆盖 | 硬限制 |
|---|---|---|
| `linear` | 流程图、UML 活动图：单列主链、判定左/右分支、多路汇合到中线、回溯绕行 | 只有三列（`-1` / `0` / `1`），四路分支排不下；不支持泳道、并行分叉条、注释框 |
| `usecase` | 用例图：左参与者 + 主用例列 + 被包含列 | 参与者一律排左侧，不支持右侧次要参与者；两人的关联用例纵向交叠时直接报错（拆图或换通道） |

**下面这些一律走 PlantUML，别拿 `layout.py` 硬凑**：类图、时序图、状态图、部署图、E-R 图、数据流图、架构图、泳道图。

判断口径就一句话：**图的结构能不能用"一条主链 + 左右分支"或"一列主用例 + 一列被包含"讲完**。能，走脚本；不能，换通道。硬凑的结果是脚本报一串冲突，或者出来一张结构对、读不懂的图。

要加版式就加一个 `Layout` 类（照 `LinearLayout` 的结构，一百多行），**不要把现有 DSL 改成通用 DSL**——一旦允许任意 `x/y` 写进 JSON，"坐标不归模型管"这条就破了，图的规模上限会跟着塌回手写水平。

## 线要直、粗细要匀

PlantUML 默认样式有两个天然缺陷，评审一眼就能看出来：

1. **曲线绕行**：默认样条布线，长距离 include 画出 S 弯，跨边界关联绕大弧线。加 `skinparam linetype ortho` 强制横平竖直。
2. **线宽不匀**：默认椭圆边框 0.5、连线 1.0、actor 小人 0.5，同一张图三种粗细。所有 `<图种>BorderThickness` 拉齐到 1.0（完整清单见 `references/snippets.md` 样板），三个易漏的：`usecaseBorderThickness`、`actorBorderThickness`、`sequenceParticipantBorderThickness`。

例外：时序图生命线 0.5 细虚线是 UML 惯例（辅助线细于消息线），actor 胶囊和数据库圆柱的 1.5 是 PlantUML 硬编码的装饰描边，`check_diagram.py` 对这两类已豁免，看到不用管。

## 用例图的箭头

参与者与用例之间写 `-->`，不要写 `--`：

```
@startuml
left to right direction
actor 专家
rectangle 农事决策系统 {
  usecase "查看任务中心" as UC1
  usecase "识别结果复核" as UC2
}
专家 --> UC1
专家 --> UC2
@enduml
```

`--` 画出来是一条没有箭头的直线，导出后与普通连线无异；评审最常见的读法是"关系没画清、方向不明"。**论文场景一律带箭头，箭头指向用例**，不指向参与者。include / extend 用 `..>`，方向指向被依赖的那一个。

手写 SVG 时同理：`<line>` 必须带 `marker-end`，且终点落在椭圆边界上（见下文交点公式）。

## 工作流

1. **定图号**：按章编号 `<章>-<序>`，如 `图 4-2`。批量改号必须从大到小倒序替换，正序会互相覆盖。
2. **数图元**：> 7 个 → 走 `layout.py` 或 PlantUML；≤ 7 个且要精细版式，才允许手写。
3. **生成并落到文件**（`.json` / `.puml` / `.svg`），不要只在对话里贴。
4. **过校验**：`check_diagram.py` 退出码 0 才继续。有问题改**源文件**再重跑，最多 3 轮。
5. **交付三样**：
   - 图文件
   - 题注：`图 4-2　系统部署图`（全角空格分隔，置于图下方居中）
   - 正文引用句：`如图 4-2 所示，……`（必须先引后出）

PlantUML 产出也要过校验：导出 SVG 后跑一遍，它同样会画出穿框线和悬空箭头——"不是我手写所以不会错"是错的。

## 校验脚本

```bash
python scripts/check_diagram.py 图.svg
python scripts/check_diagram.py 页面.html --grayscale
```

支持 `.svg` 与 `.html`（HTML 会逐个检查内嵌 SVG）。发现问题时退出码为 1。

| 项 | 判据 | 典型成因 |
|---|---|---|
| 箭头未贴合 | 箭尖离最近图元 > 1.5px | 终点写成"框边 − 2~4px" |
| 箭头悬空 | 箭尖 9px 内没有任何图元 | 目标图元被改名/挪走，线还指着老位置 |
| 图元越界 | bbox 超出 viewBox（含 line / path） | 加内容后忘放大画布 |
| 文字溢出 | 估算宽度超出 viewBox | 换了个更长的词 |
| 文字挤爆所在框 | 估算宽 > 框宽 − 8px | 文案变长没改框 |
| 连线横穿图元 | 连线（去掉两端）穿过非端点图元 | 上下层之间有节点，线直接穿过去了 |
| 连线交叉 | 两条带箭头的线相交，交点不在端点 | 只留了一条通道 |
| 图元重叠 | 两个图元 bbox 相交且非包含关系 | 层距/列距不够 |
| 终止符形状 | 写着"开始/结束"的框 `rx ≠ 高/2` | 用了工具默认圆角矩形 |
| 用例间流程箭头 | 两个椭圆之间连了实线箭头 | 把用例图当流程图用 |
| 线宽不统一 | 同一图出现 ≥0.5px 差的多档 stroke-width（虚线辅助线豁免） | 用工具默认值直接出图 |
| 非灰度颜色 | RGB 极差 > 8（`--grayscale`） | 用颜色承载语义 |

`--tolerance` 放宽贴合容差，`--json` 供程序解析。

含**故意画错**的对照图（教学用反面教材）会被逐条报出，属预期；检查对象应是成品图。

## 交点必须解出来

手写 SVG 时（≤7 图元那种），箭头终点要取目标图形的**边界坐标**。椭圆上的点不能目测：

```
((x0 + dx·t − cx)/rx)² + ((y0 + dy·t − cy)/ry)² = 1
```

取较小的 t 代回得交点。矩形则取与连线方向相交的那条边。参与者引出多条关联线时，统一从**手臂末端**出发形成扇形。

图元一多，这些交点就不是"算几道题"而是"算几十道题"，漏一个箭尖就悬空一个——`layout.py` 里这段是函数，不是心算。

## 三层参考，按顺序用

1. **`assets/examples/gallery.png`** — 20 个图例的正误对照总览，一张图看完所有图种。开工前先看这张，建立"什么是对的"的直观印象。
2. **`assets/examples/NN-<图种>-<ok|bad>.svg`** — 单个图例的完整源码，坐标原样保留。要画某类图时打开对应的 `ok` 文件，照着结构改内容，**不要从零画**。索引见同目录 `INDEX.md`。
3. **`references/snippets.md`** — 符号级片段：marker、终止符、UML 起止节点、类图关系端点、分叉粗线、椭圆交点公式、用例图布局尺寸。只画单个符号时抄这里。

`references/symbols.md` 是规则表，用来最后核对"有没有漏元素"，**不是用来起步的**。

顺序不能反：先看样例，再抄结构，最后对规则。直接从规则起步，就会把"两端半圆"脑补成 `rx="6"`。

> **样例只教形状，不教规模。** 每个 `ok` 样例都是 4–6 个图元的单符号示范，画布 300~400 宽。它们的坐标是手工配平过的，只对那个图元数成立。别拿 300 宽的画布去塞 20 个节点，也别指望"照着改内容"就能改出 20 个来——改到第 8 个，层距和分支偏移就已经不在同一个坐标系里了。

> 图例由 `scripts/extract_examples.py` 从规范手册自动抽取。手册更新后重跑：
> `python scripts/extract_examples.py 手册.html --out assets/examples`

## 输出禁忌

- 图内不写标题，标题归题注
- 参与者—用例的关联线必须带箭头（`-->` 或 `marker-end`），光杆线一律返工
- 处理框不写数据库字段值、方法签名、代码变量名
- 不用界面截图充当系统图
- 不用颜色区分语义（论文默认黑白打印）
- 同一流程不重复画成多种图种
