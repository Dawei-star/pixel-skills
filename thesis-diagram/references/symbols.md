# 符号定义速查

按图种查。每节给「必需元素 → 绘制规则 → 高频错误」，画之前扫一眼对应小节。

---

## 一、流程图（GB 1526-89 / ISO 5807:1985）

### 符号

| 符号 | 形状 | 用途 |
|---|---|---|
| 终止符 | 两端半圆的扁长形（跑道形，`rx = 高/2`） | 开始、结束、暂停 |
| 处理 | 直角矩形 | 赋值、计算、动作 |
| 判断 | 菱形 | 条件分支 |
| 输入/输出 | 平行四边形 | 数据读入与输出 |
| 文档 | 底边波浪的矩形 | 打印、纸质文档 |
| 预定义处理 | 两侧带竖线的矩形 | 调用子流程 |
| 连接符 | 圆 | 跨页、断线接续 |
| 人工操作 | 上宽下窄的梯形 | 须由人执行的动作 |
| 存储数据 | 圆柱 | 数据库、文件 |
| 注释 | 左侧带尖角的虚线框 | 补充说明 |

### 规则

- 处理框**单入口、单出口**；判断框单入口、多出口
- 每个出口必须标条件（是／否，或 `60 ≤ c < 85` 这类区间）
- 流向自上而下、自左而右；回退与循环才允许逆向，且画成明确回跳线
- 多线汇合处打实心小圆点，或让各分支独立连到目标框
- 线交叉处画跨线小弧
- 框内只写业务动作

### 高频错误

- 用圆角矩形写"开始/结束" —— 两套规范都不认
- 菱形出口不标是/否
- 处理框拉出两条出线（把判断省成了处理）
- 两条分支叠成 T 形却没画汇合节点
- 写进 `status = 3` 这类字段值

## 二、UML（2.5.1）

### 2.1 用例图

必需：参与者（小人，名称在下）、系统边界（矩形，系统名在框内顶部）、用例（椭圆，动宾短语）

| 关系 | 画法 | 方向 |
|---|---|---|
| 关联 | 实线 + 箭头（**必画，别省**） | 指向用例 |
| include | 虚线 + 开放箭头 + `«include»` | 主用例 → 被包含用例 |
| extend | 虚线 + 开放箭头 + `«extend»` | 扩展用例 → 基础用例 |
| 泛化 | 实线 + 空心三角 | 子 → 父 |

- 参与者必须在边界外，用例必须在边界内
- **分层排布**：主用例排一列，被 include / extend 的用例整体右移一列并上下错开，连线自然呈扇形。全堆一列会让依赖关系看不出来
- 用例总数控制在 10–20，多了按模块拆图

高频错误：**参与者与用例之间没有箭头**（规范上可省，论文里别省——评审多半按"关系没说清"记）；用例之间画流程箭头（用例图不表达顺序）；参与者画进边界内；include / extend 方向反。

### 2.2 类图

必需：三层矩形（类名 / 属性 / 方法）、可见性符号、关系线、多重性

| 关系 | 画法 |
|---|---|
| 关联 | 实线（可加开放箭头表方向） |
| 聚合 | 空心菱形，**菱形贴整体端** |
| 组合 | 实心菱形，**菱形贴整体端** |
| 泛化 | 实线 + 空心三角，指向父类 |
| 实现 | 虚线 + 空心三角，指向接口 |
| 依赖 | 虚线 + 开放箭头 |

- 格式 `可见性 名称: 类型`，如 `- amount: BigDecimal`；`+` public、`-` private、`#` protected、`~` package
- 接口标 `«interface»`

高频错误：菱形贴错端；成员没有类型和可见性；多重性缺失。

判断聚合还是组合：问"整体没了，部分还活着吗"。订单删了订单项跟着删 → 组合；班级解散了学生还在 → 聚合。

### 2.3 时序图

必需：参与者框、生命线（虚线）、激活条（窄矩形）、消息、组合片段

| 消息 | 画法 |
|---|---|
| 同步调用 | 实线 + 实心箭头 |
| 异步消息 | 实线 + 开放箭头 |
| 返回 | **虚线** + 开放箭头 |
| 自调用 | 折回自身激活条 |

- 参与者从左到右按调用先后排列
- 组合片段 `alt` / `opt` / `loop` / `par`，左上角五边形标签，分支写 `[条件]`
- 消息名写业务动作，不写方法签名

高频错误：返回用实线实心箭头；没有激活条；消息名写成 `submit(OrderDTO)`。

### 2.4 活动图

必需：初始节点（实心圆，无文字）、动作（圆角矩形）、决策（菱形）、终止节点（实心圆 + 外环）

- 条件标在菱形的每条出边上
- 并发用**粗黑横线**（fork / join bar），不用菱形
- 动作名用动词短语

高频错误：用圆角矩形写"开始/结束"（UML 里圆角矩形是动作框，等于说"这是个叫开始的动作"）；用菱形做并发分叉。

### 2.5 状态图

必需：初始/终止节点、状态（圆角矩形）、转移（实线箭头）

- 状态名用状态词：草稿、待审核、已发布、已驳回。判断法：能接在"当前处于——"后面的才是状态
- 转移标 `事件[守卫条件]/动作`
- 每个状态可达，除终态外都要有出边
- 状态数控制在 5–9

高频错误：状态名写成动作（读起来像活动图）；转移不标事件。

### 2.6 部署图

必需：节点（**立体盒**：正面矩形 + 顶面与侧面平行四边形）、构件（`«artifact»`）、通信路径

- 节点标注 `«device»` 或 `«executionEnvironment»`
- 通信线标协议：`HTTPS`、`JDBC`、`Bolt`
- 外部依赖（对象存储、第三方 API）放节点之外

高频错误：用平面矩形画节点，丢失"物理运行环境"语义；把逻辑分层画进部署图（那是架构图）。

### 2.7 组件图 / 包图

- 构件：矩形 + 左上角构件图标 + `«component»`
- 提供接口：棒棒糖（圆在提供方）
- 需求接口：插座（半圆在需求方）
- 包：文件夹形

## 三、E-R 图

| 记法 | 实体 | 联系 | 属性 | 适用 |
|---|---|---|---|---|
| 陈氏 Chen | 矩形 | 菱形 | 椭圆 | 概念模型、教学 |
| IE 鸦脚 | 表框（含字段） | 连线 + 端点符号 | 表内字段行 | 物理模型、工程文档 |

鸦脚端点：`‖` 一且仅一、`‖o` 零或一、`≺` 零或多、`‖≺` 一或多。

- 一张图只用一种记法，绝不混用
- 关系两端都标基数
- PK / FK 显式标注
- 跨库关联（关系库 ↔ 图库 / 文档库）无法建物理外键时，用**虚线**画并在图注说明"由应用层保证一致性"

高频错误：菱形（陈氏）与表框（鸦脚）混用；关系线两端不标基数。

## 四、数据流图（DFD）

必需：外部实体（矩形）、处理（圆角矩形，编号 + 动词）、数据流（箭头，标数据名）、数据存储（右开口矩形，编号 D1/D2）

- 自顶向下分层：顶层图 → 0 层 → 1 层，每层输入输出平衡
- 每个处理至少一进一出（无输出的叫"黑洞"，无输入的叫"奇迹"）
- 两个处理之间不能直接连线，必须经数据存储或外部实体
- **不画判断菱形**，DFD 不表达控制流

## 五、架构图

- 表达逻辑分层，不是物理部署
- 每个方框标**具体技术栈**，不写空泛的"业务层"
- 同层元素对齐排布，大小一致
- 依赖方向单向自上而下

## 通用禁忌

| 禁忌 | 原因 |
|---|---|
| 图内写标题 | 标题归题注，重复 |
| 用颜色承载语义 | 论文默认黑白打印 |
| 截图当插图 | 打印发虚，须用矢量或 ≥300dpi |
| 图号不按章 | 全文重号或跳号 |
| 图题位于图上方 | 图题在下、表题在上，无例外 |
| 正文未引用先出图 | 必须先"如图 X-X 所示" |
